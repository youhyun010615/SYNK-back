## 서비스 개요

**SYNK** — 랜덤 알림으로 친구 그룹이 동시에 짧은 영상 미션을 수행하고, 자동으로 콜라주를 생성·저장하는 실시간 동기화 SNS 앱.

> "우리는 지금, 같은 순간을 산다."

### 핵심 플로우

1. **랜덤 사이렌** — 하루 1~5회, 예고 없이 방 멤버 전원에게 동시 푸시 알림
2. **5분 타임어택** — 알림 확인 후 5분 이내 3~5초 영상 미션 제출
3. **Group Collage** — 전원 제출 or 제한 시간 종료 시 자동 콜라주 합성 (AWS Lambda + FFmpeg)
4. **SYNKLOG** — 당일 콜라주를 이어붙인 일별 릴스 영상
5. **도감** — 완료 미션이 개인 도감에 자동 저장

### 기술 스택

| 구분 | 기술 |
|---|---|
| 백엔드 | Spring Boot 4.0.6, JPA/Hibernate, PostgreSQL (Supabase) |
| 인프라 | AWS EC2 (Ubuntu), Docker, GitHub Actions CI/CD |
| 스토리지 | AWS S3 (`synk-videos`, `ap-northeast-2`) |
| 영상 처리 | AWS Lambda (Python 3.11) + FFmpeg |
| 프론트엔드 | React (Vercel 배포) |
| 푸시 알림 | Firebase FCM |

## 작업 1 — 콜라주 기능 구현 (AWS Lambda + FFmpeg)

> **PR:** [#77](https://github.com/youhyun010615/SYNK-back/pull/77), [#78](https://github.com/youhyun010615/SYNK-back/pull/78) | **Issue:** [#76](https://github.com/youhyun010615/SYNK-back/issues/76)

### 배경

미션 영상을 멤버별로 따로 보는 것이 아니라, 전원 제출 또는 미션 만료 시점에 자동으로 분할 화면 콜라주를 합성해서 앨범에 저장하는 기능이 필요했다.

### 요구사항

- 1~10명 멤버 대응 분할 레이아웃 (9:16, 1080×1920)
- 전원 제출 즉시 또는 미션 만료 시 자동 트리거
- 비동기 처리 (Lambda 응답 기다리지 않고 콜백으로 결과 수신)
- 생성된 콜라주 S3 저장 + 썸네일 추출

### 레이아웃 설계

```
1명: [1]
2명: [1][1] (상하 1:1)
3명: [1][2] (상1 + 하2)
4명: [2][2]
5명: [2][3]
6명: [3][3]
7명: [3][4]
8명: [4][4]
9명: [3][3][3]
10명: [3][3][4]
```

### 1-1. AWS Lambda 함수 생성

**파일:** `lambda/collage_function.py`

**주요 동작:**
1. 백엔드로부터 `missionId`, `submissions[]`, `callbackUrl`, `callbackSecret` 수신
2. S3에서 각 멤버 영상 다운로드
3. FFmpeg `filter_complex`로 분할 화면 합성 (최대 30초)
4. 완성된 콜라주 영상 + 썸네일(첫 프레임)을 S3 업로드
5. 백엔드 콜백 URL로 결과 POST

**Lambda 환경 변수:**

| 키 | 값 |
|---|---|
| `S3_BUCKET` | `synk-videos` |
| `AWS_REGION_NAME` | `ap-northeast-2` |
| `COLLAGE_CALLBACK_SECRET` | `synk-collage-secret-2024` |
| `COLLAGE_CALLBACK_URL` | `https://api.synk.ai.kr/api/collages/callback` |

**Lambda 설정:**
- 함수명: `synk-collage`
- 런타임: Python 3.11
- 메모리: 3008 MB
- 타임아웃: 5분
- IAM 역할: `synk-collage-role-q9fs56hp` (S3 Read/Write 권한 포함)
- FFmpeg 레이어: 직접 CloudShell로 빌드해서 레이어 생성 (`arn:aws:lambda:ap-northeast-2:178382097695:layer:ffmpeg:1`)

> **참고:** AWS 공개 FFmpeg 레이어 ARN은 접근 거부 오류가 발생해 CloudShell에서 직접 빌드했다.

### 1-5. 백엔드 — 트리거 시점 2곳

**① 전원 제출 시 즉시 트리거** (`SubmissionService.java`)

```java
// 제출 후 전원 완료 여부 확인
int totalMembers = roomMemberRepository.countByRoom(room);
long submittedCount = submissionRepository.findByMission(mission).stream()
    .filter(s -> s.getStatus() == SUBMITTED).count();
if (submittedCount >= totalMembers) {
    collageService.triggerCollageIfReady(mission);
}
```

**② 미션 만료 시 트리거** (`MissionScheduler.java`)

```java
// processExpiredMissions()에서 mission.complete() 후
boolean hasSubmissions = submissions.stream()
    .anyMatch(s -> s.getStatus() == SUBMITTED);
boolean collageExists = collageRepository.findByMission(mission).isPresent();
if (hasSubmissions && !collageExists) {
    collageService.triggerCollageIfReady(mission);
}
```

## 작업 2 — 서버 장애 복구

### 배경

콜라주 기능 배포 후 서버가 시작 실패. 원인은 `COLLAGE_CALLBACK_SECRET` 환경변수 미설정.

### 오류 메시지

```
Could not resolve placeholder 'COLLAGE_CALLBACK_SECRET'
in value "${COLLAGE_CALLBACK_SECRET}"
```

### 원인

`deploy.yml`에 새 환경변수 3개를 추가했지만, 기존에 실행 중이던 Docker 컨테이너의 `~/synk.env`에는 반영이 안 된 상태였다.

### 복구 과정

1. EC2 SSH 접속
   ```bash
   ssh -i ~/Desktop/SYNKback.pem ubuntu@13.125.99.225
   ```

2. `~/synk.env`에 환경변수 수동 추가
   ```bash
   echo "AWS_LAMBDA_COLLAGE_FUNCTION=synk-collage" >> ~/synk.env
   echo "COLLAGE_CALLBACK_SECRET=synk-collage-secret-2024" >> ~/synk.env
   echo "COLLAGE_CALLBACK_URL=https://api.synk.ai.kr/api/collages/callback" >> ~/synk.env
   ```

3. Docker 컨테이너 재실행 (이미지명 확인 후)
   ```bash
   docker images  # hihyun/synk 확인
   docker run -d --name synk --restart unless-stopped \
     -p 8080:8080 --env-file ~/synk.env hihyun/synk:latest
   ```

4. 서버 기동 확인
   ```bash
   docker logs synk 2>&1 | grep -E "Started|ERROR" | tail -3
   # → Started SynkApplication in 17.903 seconds
   ```

### 근본 원인 해결

`deploy.yml`에 3개 환경변수 영구 추가 + GitHub Secrets 등록으로 이후 자동 배포 시 동일 문제 방지.

## 작업 3 — Lambda 코드 버그 수정

> **관련 이슈:** Lambda TypeError 수정

### 오류

```
[ERROR] TypeError: unsupported operand type(s) for //: 'int' and 'list'
```

### 원인

`get_cells()` 함수에서 `rows_config`의 각 row가 `[1]`, `[2]`, `[3]` 같은 **리스트**인데, 이를 바로 정수처럼 나눗셈 연산에 사용했다.

```python
# 버그
for cols in rows_config:       # cols = [2] (리스트)
    cell_w = CANVAS_W // cols  # int // list → TypeError!
```

### 수정

```python
# 수정
for row in rows_config:
    cols = row[0]              # [2] → 2 (정수 추출)
    cell_w = CANVAS_W // cols
```

### 배포

```bash
cd lambda
zip collage_function.zip collage_function.py
aws lambda update-function-code \
  --function-name synk-collage \
  --zip-file fileb://collage_function.zip \
  --region ap-northeast-2
```

## 작업 4 — CollageResponse 필드 추가

> **PR:** [#80](https://github.com/youhyun010615/SYNK-back/pull/80) | **Issue:** [#79](https://github.com/youhyun010615/SYNK-back/issues/79)

### 배경

앨범 화면에서 콜라주 버튼 클릭 시 프론트엔드가 크래시.

```
TypeError: Cannot read properties of undefined (reading 'length')
```

### 원인

프론트엔드 `CollageItem` 타입이 `participants`, `missionTitle`, `missionStartAt` 필드를 필요로 하는데, 백엔드 `CollageResponse`에 해당 필드가 없었다.

### 수정 내용

**`CollageResponse.java`에 추가된 필드:**

| 필드 | 설명 |
|---|---|
| `missionTitle` | `mission.missionTemplate.title` |
| `missionStartAt` | `mission.targetedAt` (ISO string) |
| `participants` | 방 멤버 전원 + 제출 여부/영상 URL |

**`CollageParticipant` 내부 클래스:**

```java
public static class CollageParticipant {
    private Long userId;
    private String name;
    private String profileImage;
    private String videoUrl;
    private String submittedAt;
    private String state;  // "done" | "waiting"
}
```

**`CollageService.getCollagesForDate()` 수정:**

- 기존: `CollageResponse.from(collage)` — 단순 변환
- 수정: `CollageResponse.from(collage, members, submissions)` — 멤버 목록 + 제출 현황 함께 조회

## 작업 5 — JVM 타임존 고정 및 미션 중복 생성 버그 수정

> **PR:** [#82](https://github.com/youhyun010615/SYNK-back/pull/82) | **Issue:** [#81](https://github.com/youhyun010615/SYNK-back/issues/81)

### 배경

서버 로그에서 `duplicate key value violates unique constraint` 오류가 지속 발생.

```
Detail: Key (room_id, date, time_slot_id)=(46, 2026-06-18, 31) already exists.
```

### 원인 분석

두 가지 문제가 복합적으로 작용했다.

**문제 1 — JVM 타임존이 UTC**

EC2 서버의 JVM 기본 타임존이 UTC라서 `LocalDate.now()`, `LocalDateTime.now()` 호출 시 KST와 최대 9시간 차이 발생. 스케줄러가 KST 기준 자정(00:00)에 실행되어도 날짜 계산이 잘못될 수 있었다.

**문제 2 — 중복 생성 방지 로직 누락**

`MissionScheduler.createDailyMissions()`에서 미션 저장 전 이미 동일한 `(room_id, date, time_slot_id)` 조합이 존재하는지 확인하지 않았다. 서버 재시작 시 스케줄러가 다시 실행되면 같은 미션을 또 생성하려다 DB 제약조건 위반으로 500 오류 발생.

---

### 수정 1 — JVM 타임존 전역 고정

**`SynkApplication.java`에 추가:**

```java
@PostConstruct
public void init() {
    TimeZone.setDefault(TimeZone.getTimeZone("Asia/Seoul"));
}
```

> 스케줄러 전체(`createDailyMissions`, `activateMissions`, `processExpiredMissions`)의 시간 계산이 KST 기준으로 통일된다.

---

### 수정 2 — 중복 미션 생성 방지

**`MissionScheduler.createDailyMissions()`에 추가:**

```java
for (int i = 0; i < count; i++) {
    MissionTimeSlot slot = availableSlots.get(i);
    // 이미 존재하면 skip
    if (missionRepository.existsByRoomAndDateAndTimeSlot(room, today, slot)) continue;
    missionRepository.save(Mission.builder()
        .room(room)
        .missionTemplate(templates.get(i % templates.size()))
        .timeSlot(slot)
        .date(today)
        .build());
}
```

## 미션 알림 발송 로직 요약

```
자정 00:00 (KST)
└── createDailyMissions()
    ├── 풀방인 경우만 미션 생성
    ├── missionStartTime ~ missionEndTime 내 슬롯 랜덤 선택
    └── 상태: PENDING

매분 (60초 간격)
├── activateMissions()
│   ├── PENDING 미션 중 현재 시각과 slotTime 일치하는 것 ACTIVE로 변경
│   └── 방 멤버 전원에게 FCM 푸시 발송 (missionAlert=true인 경우)
│
└── processExpiredMissions()
    ├── ACTIVE 미션 중 deadline(시작+5분) 지난 것 처리
    ├── 미제출자 → MISSED Submission 자동 생성
    ├── 제출자 → 도감(CollectionRecord) 기록 생성
    ├── 미션 상태 COMPLETED
    └── 제출자 있고 콜라주 없으면 → Lambda 트리거
```
