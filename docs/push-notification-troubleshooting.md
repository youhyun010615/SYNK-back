# 푸시 알림 트러블슈팅 가이드

"알림이 안 온다"는 제보가 들어왔을 때 원인을 빠르게 좁히기 위한 체크리스트.
SYNK는 iOS PWA(홈 화면 추가) + FCM 웹푸시 구조다.

## 1. 증상별 원인 정리

| 증상 | 원인 | 확인 방법 |
|---|---|---|
| 특정 방만 미션이 안 옴 | 자정엔 정원 미달이다가 낮에 풀방이 된 방 → 당일 미션 0개 | `missions`에서 `date = CURRENT_DATE` 방별 개수 |
| 특정 사용자만 알림이 안 옴 | `user_fcm_tokens`에 토큰이 없음 (권한 미허용 / "나중에" 선택 / Safari 탭 사용) | 사용자별 토큰 수 조회 |
| 어제는 오는데 오늘부터 안 옴 | 폰의 푸시 구독이 죽었는데 FCM은 성공(200)을 반환 → 서버가 감지 불가 | 서버 로그 "FCM 전송 성공" + 폰 무음 |
| 같은 사람인데 방마다 다름 | 계정이 여러 개(카카오/구글)이고 토큰은 계정 단위로 귀속 | `room_members` + `user_fcm_tokens` 대조 |

## 2. 서버 쪽 진단 순서

1. 컨테이너 상태: `docker ps`, `docker inspect synk` 의 RestartCount (OOM 재발 여부)
2. 미션 발동 로그: `미션 활성화: missionId=...`
3. 사용자별 FCM 결과: `FCM 전송 성공` / `FCM 토큰 없음` / `FCM 전송 실패`
4. DB 대조
   - 풀방인데 오늘 미션이 0개인 방이 있는지
   - 대상 사용자의 토큰이 언제 등록됐는지 (`created_at`)
5. nginx access.log 에서 해당 기기의 `PUT /api/users/fcm-token` 요청 유무 확인
   - 앱을 켰는데 등록 요청이 없다 → 알림 권한이 "허용"이 아니거나 FE에서 토큰 발급이 실패한 것

## 3. 알아둘 점

- **FCM의 200 응답 ≠ 기기 도착.** iOS 웹푸시 구독이 죽어도 FCM은 성공으로 응답하므로,
  서버의 `UNREGISTERED` 정리 로직으로는 죽은 토큰을 걸러낼 수 없다.
- 토큰은 기기 단위로 저장되고, 같은 토큰으로 다시 로그인하면 소유 계정만 갱신된다 (`reassignTo`).
- FE의 자동 재등록은 앱이 새로 시작될 때 한 번만 실행되며, 실패해도 화면에 표시되지 않는다.
- 알림 권한 팝업은 "허용이 아님 + 한 번도 안 물어봄"일 때만 뜬다. "나중에"를 누르면 다시 묻지 않는다.

## 4. 사용자 복구 방법

홈 화면에서 앱 삭제 → Safari로 접속 → 공유 → 홈 화면에 추가 → 새 아이콘으로 열어 로그인 →
"알림 허용하기" 허용. 구독·권한·"이미 물어봄" 기록이 모두 초기화된다.

## 5. 개선 후보

1. 앱 시작/포그라운드 복귀 때마다 구독을 점검하고 죽었으면 재등록, 실패 사유를 화면에 표시
2. 푸시 수신 시 서비스워커가 서버에 수신 확인을 보내고, 연속 미수신 기기에 "알림 다시 연결" 배너 노출
3. "나중에" 선택을 영구 무시하지 않고, 알림이 꺼져 있으면 설정 안내 배너를 계속 노출
4. (장기) 네이티브 앱(APNs) 전환 — 앱스토어 심사 대비 필요 항목:
   사용자 콘텐츠 신고·차단, Sign in with Apple, Capacitor 등 네이티브 기능 연동
