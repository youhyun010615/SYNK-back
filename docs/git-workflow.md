# Git 작업 흐름

`develop` / `release` 브랜치를 따로 두는 정통 Git Flow 대신, **`main` 에서 작업 브랜치를 분리하고 PR 로 통합하는 GitHub Flow** 를 사용한다.

## 1. 커밋 메시지

```
<type>: <한국어 작업 요약>
<type>: <한국어 작업 요약> (#이슈번호)
```

| 타입 | 용도 |
|---|---|
| `feat` | 새로운 기능 추가 |
| `fix` | 오류 및 잘못된 동작 수정 |
| `refactor` | 기능 변경 없이 코드 구조 개선 |
| `docs` | 문서 작성 및 수정 |
| `test` | 테스트 추가 및 수정 |
| `chore` | 설정·환경 등 기타 작업 |

작성 기준

- 한 커밋에는 하나의 작업 목적만 담는다. (예: 수정과 테스트는 커밋을 나눈다)
- 관련 없는 여러 도메인의 변경을 섞지 않는다.
- "수정", "작업 완료" 대신 변경 내용을 구체적으로 쓴다.
- 필요하면 기능명세서의 기능 ID 를 커밋이나 PR 에 포함한다.

## 2. 이슈

기능 개발과 버그 수정 두 가지 형식으로 관리한다.

| 구분 | 제목 형식 | 예시 |
|---|---|---|
| 기능 개발 | `✨[Feat] 작업 내용` | `✨[Feat] 기존 방 알림·미션 발동 중단, 신규 방부터만 푸시 적용` |
| 버그 수정 | `🐛[Fix] 문제 내용` | `🐛[Fix] 방 생성 시 종료 시각 24:00 입력하면 500 오류` |

기능 개발 이슈 본문 항목: 작업 타입 / 작업 영역 / 상세 내용 / 관련 API·화면·테이블 / 완료 조건 / 예상 소요 기간 / 참고 사항

버그 수정 이슈 본문 항목: 버그 내용 / 재현 방법 / 기대 동작 / 실제 동작 / 발생 영역 / 관련 API·화면·테이블 / 에러 로그·스크린샷 / 우선순위 / 수정 완료 조건 / 참고 사항

공통 규칙

- 템플릿 항목과 순서를 유지한다.
- 해당하지 않는 항목은 삭제하지 않고 `-` 로 표시한다.
- 관련 API·화면·테이블과 완료 조건을 명시한다.

## 3. 브랜치

| 브랜치 | 역할 | 예시 |
|---|---|---|
| `main` | 기능 통합 및 배포 기준 | `main` |
| `feature/*` | 기능 단위 개발 | `feature/be-disable-legacy-room-alerts` |
| `fix/*` | 버그 수정 | `fix/room-end-time-24h` |

기본 형식은 `feature/<도메인 또는 화면>` 이며, FE·BE 를 구분할 때는 `feature/be-...`, `feature/fe-...` 를 쓴다.

## 4. 작업 순서

1. **이슈 등록** — 작업 범위, 관련 API·화면, 완료 조건을 정의
2. **작업 브랜치 생성** — 최신 `main` 기준으로 분리
3. **개발 및 커밋** — 작업 목적별로 나누고 커밋 메시지 규칙 적용
4. **최신 변경 통합 및 검증** — 필요하면 `main` 변경을 반영하고 충돌·동작 확인
5. **PR 생성** — 작업 브랜치에서 `main` 으로, 관련 이슈 연결
6. **PR 병합** — `main` 직접 push 대신 PR 로 통합 (Squash Merge 를 원칙으로 한다)
7. **배포** — `main` 에 반영되면 GitHub Actions 가 빌드 → Docker 이미지 push → EC2 배포를 실행

## 5. PR

제목: `<type>: <한국어 작업 요약>`

본문

```markdown
## 관련 Issue
- Closes #이슈번호

## 작업 내용
- 구현 또는 수정한 내용
- 주요 변경 사항

## 확인 사항
- [ ] 로컬에서 정상 동작을 확인했습니다.
- [ ] 불필요한 파일·민감 정보가 포함되지 않았습니다.
- [ ] UI 변경 시 화면 캡처를 첨부했습니다. (해당 시)
- [ ] API 변경 시 관련 문서를 함께 수정했습니다. (해당 시)
```

- `Closes #번호` 로 관련 이슈를 연결한다.
- 실제로 확인한 항목만 체크한다.
- UI 변경은 캡처를, API 변경은 문서 수정 여부를 확인한다.
- 스쿼시 머지 시 커밋 제목에는 PR 번호 대신 이슈 번호 `(#이슈번호)` 를 붙인다.
